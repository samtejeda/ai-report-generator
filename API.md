# API.md

Inventory of every endpoint and server action. Updated in the same commit as any new or changed route (owner: `backend-builder`). No orphan test routes.

## Conventions

- Resource-oriented paths under `app/api/`, plural nouns, kebab-case: `/api/clients`, `/api/reports/{id}/sections/{sectionId}`.
- Methods: `GET` read, `POST` create/action, `PATCH` partial update, `DELETE` remove (soft delete unless a hard-deletion request).
- Every handler: authenticate, authorize (role + `organization_id`), validate input with a schema, call a tenant-scoped data function, write an audit event, return minimal fields.
- Errors: JSON `{ "error": { "code": string, "message": string } }` with correct status codes (400 validation, 401 unauthenticated, 403 unauthorized, 404 not found within the caller's org, 409 conflict, 429 rate limited, 500 generic with no internals).
- Return 404 (not 403) for resources in another organization, to avoid leaking existence.
- Lists are paginated (cursor or limit/offset with a max).
- Never include `password_hash`, tokens, or other tenants' fields in responses.
- Never log request bodies; audit events carry ids, not PHI.
- Generation endpoints stream via the Vercel AI SDK and call inference only through `lib/ai/inference.ts`.

Only the twelve `/api/auth/*` endpoints above are reachable; the route (`app/api/auth/[...all]/route.ts`) answers 404 for every other Better Auth path (sign-up, get-session, list-sessions, update-user, social login, ...). The list lives in `lib/auth/route-policy.ts` and a test keeps it equal to this table. POSTs are also checked for origin (CSRF) and redirect targets.

## Pages

Everything except the public pages needs a session. `proxy.ts` sends a request with no session cookie to `/login` (307) or answers an API call 401; it is a convenience, and every page and handler re-checks for itself. The public pages and endpoints are the one list in `lib/auth/public-surface.ts`.

| Path | Auth | Purpose |
|---|---|---|
| `/login` | Public | Email + password form, then the code step (authenticator or backup code; an unchecked "Trust this device for 14 days" box). |
| `/forgot-password` | Public | Requests a reset link; the same message whether or not the address has an account. |
| `/reset-password` | Public (the emailed token is the credential) | Choose a new password; the token is removed from the address bar once read, and no Referer is sent. |
| `/account/mfa` | Password session without MFA yet (`getEnrollingSessionOrNull()`); already-enrolled users are sent to `/account` | Three steps: confirm password, add the setup key to an authenticator app and type the first code, save the backup codes (shown once). |
| `/account` | Session (`(app)` layout and `requireSession()` inside the page) | Shows the signed-in role, a change-password form (current password, new password twice, "sign out my other sessions"; calls `POST /api/auth/change-password`) and a sign-out button. |
| `/clients` | Session; owner, associate or admin (`(app)/clients` layout and `requireRole()` inside the page). | Plain list of the clients the caller may see (owner: the practice; associate or admin: assigned / granted only, so an admin with no grant sees an empty list), each linking to its page, and a "New client" link for owner and associate. Audit `client.listed`. |
| `/clients/new` | Session; owner or associate (`requireRole()` inside the page; an admin gets the 404 page). | Plain form to create a client (name, date of birth, grade level, external ID). Calls `POST /api/clients`. |
| `/clients/{id}` | Session; owner, associate or admin (`requireRole()` inside the page), and only a client the caller may see; anything else is the 404 page. | One client. Owner and associate get an edit form (`PATCH /api/clients/{id}`); the owner also gets a delete button (`DELETE`); an admin with a grant reads only. Reports of the client are listed here, with a "New report" button for owner and associate. Audit `client.viewed`, `report.listed`. |
| `/reports/{id}` | Session; owner, associate or admin (`(app)/reports` layout and `requireRole()` inside the page), and only a report whose client the caller may see; anything else is the 404 page. | One report: status, one box per section (owner and associate may save while the report is draft, generated or error; an admin with a grant, and everyone once it is generating or finalized, read only), each section's version history, and a Finalize button when the status is `generated`. Audit `report.viewed`. |
| `/admin` | Session; **owner only** (`(app)/admin` layout and `requireRole("owner")` inside the page); anyone else gets the 404 page and an audited denial. | Plain index of the practice administration screens. |
| `/admin/users` | Same as `/admin`. | The practice's people, deactivated ones included. Per person, only what the who-may-change-whom rule allows: change role (`PATCH /api/admin/users/{id}`), deactivate and reactivate (`POST .../deactivate`, `.../reactivate`), and reset authenticator (`POST .../reset-mfa`, needs a sign-in from the last 5 minutes; an older one shows a message and a sign-out button). Nothing for oneself. Not audited by the page (the routes audit the changes). |
| `/admin/assignments` | Same as `/admin`. | Active assignments with client and person named (joined on the server; the API returns ids only), an End button each (`DELETE /api/admin/assignments/{id}`), and an Assign form (`POST /api/admin/assignments`) offering active associates and admins and the practice's clients. Audit `client.listed` (role only). |
| `/admin/inference-endpoint` | Same as `/admin`. | The practice's current endpoint and a form to set (`PUT /api/admin/inference-endpoint`, needs a recent sign-in) or clear it. The server is the only judge of the address. |
